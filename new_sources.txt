
Offline Survival Repository Research
Executive summary
The repository currently defines 52 sources in a single centralized manifest, manifests/sources/catalog.yaml: 34 English sources and 18 Spanish sources. The app profiles are defined separately in manifests/profiles/*.yaml, with five English profiles, five Spanish profiles, and five bilingual composite profiles. English coverage is substantially broader in overall count and in “rebuild civilization” topics; Spanish coverage is narrower but already includes some strong official preparedness material in the smallest profile, such as WHO Basic Emergency Care (Spanish), WHO quick cards, FEMA CERT in Spanish, and a CDC emergency-kit resource. 

The repository is strongest today in these areas: offline encyclopedic knowledge, repair and rebuilding, basic emergency medicine, and practical reference collections. It is weaker in authoritative household emergency preparedness and civil-protection guidance, especially in English. The most noticeable gap is that the English “survival-essential” tier does not currently include FEMA/Ready.gov or Red Cross first-line household preparedness documents, while the Spanish “survival-essential-es” tier already includes official emergency-preparedness items. 

My highest-confidence recommendation is to add a small set of low-size, high-authority PDFs to the essential profiles in each language: FEMA/Ready family-planning and preparedness PDFs, IFRC first-aid guidance, IFRC household water treatment guidance, Spain’s official family emergency plan, and Spain’s 2024 citizen guides for self-protection, floods, wildfires, earthquakes, and adverse weather. These additions are directly relevant to the project’s use case, are authoritative, and fit the repository’s offline-first design. 

During validation, I also captured first-page screenshot evidence for several of the recommended PDFs, including the IFRC 2025 first-aid guidelines, Spain’s family emergency plan worksheet, and WHO’s Spanish community first-aid pocket guide. 

Repository structure and profile architecture
All source definitions are centralized in manifests/sources/catalog.yaml. The repository tree also contains manifests/profiles/, which defines profile composition and intended use. The profile files visible in the repo include survival-essential*, survival-plus*, civilization-core*, civilization-rebuild*, and civilization-max*, with English, Spanish, and bilingual variants. 

The profile logic is hierarchical. English profiles build upward from survival-essential to survival-plus, then civilization-core, civilization-rebuild, and civilization-max; Spanish follows the same ladder; bilingual profiles are composites that include the English and Spanish profiles at the same tier. That means a source explicitly attached to survival-essential is effectively inherited by all larger English profiles and by the bilingual profiles that include them.

Analytical reading of the current source mix
The current profile design is coherent: essential focuses on lightweight survival and medicine; plus adds practical repair/agriculture depth; core adds reconstruction and community reference; rebuild adds broader science, literature, and education; max expands preservation breadth. 

What is missing is not structure, but authoritative preparedness content density. In English, official household-preparedness and civil-defense documents are comparatively thin in the current manifests. In Spanish, the smallest profile already includes more official preparedness material than English, but it still lacks Spain-specific civil-protection guides that are directly on-point for offline resilience.

Suggested implementation logic
For the repository’s current profile philosophy, the cleanest strategy is:

Put compact, household-critical PDFs in survival-essential / survival-essential-es.
Put deeper first-aid manuals and extended hazard annexes in survival-plus / survival-plus-es.
Put system, framework, and organized emergency-care references in civilization-core and above.
That preserves the size discipline of the profile ladder while significantly improving authority and preparedness coverage. The existing YAML descriptions already support this progression model. 

Open questions and limitations
A few details remain worth noting.

The repository does not maintain separate manifest files for English and Spanish sources; instead, both languages live in the same centralized source catalog and are differentiated by the language field and by profile references. That is clear in the current tree and catalog layout. 

For source-to-profile mapping, I treated bilingual profiles as effective inheritances rather than direct source references, because the bilingual YAMLs are composites that include the same-tier English and Spanish profiles rather than listing sources independently. That interpretation follows the profile include graph in the profile YAMLs. 

I also excluded some otherwise appealing documents because I could not confirm a stable, direct-download URL in-session without ambiguity. In other words, the recommendation set above is deliberately conservative: it favors validated file URLs over broader but less certain coverage.
